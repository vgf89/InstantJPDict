nav_graph_core — Rust library behind libnav_graph_core.so
========================================================

Bundled as : lib/arm64-v8a/libnav_graph_core.so (709 KB)

  A Rust `cdylib` (nav_graph_core/Cargo.toml, built by
  nav_graph_core/build_nav_graph.sh) that computes the OCR navigation graph and
  is called from Kotlin through UniFFI-generated bindings
  (app/src/main/java/uniffi/nav_graph_core/nav_graph_core.kt).

This app's own code
-------------------

  index).

Rust dependencies compiled into the same shared object
------------------------------------------------------

  The crate's normal-dependency closure is reproduced in this index as one entry
  per crate, with the licence text each crate ships in its own published source.
  Generated by tools/gen_rust_license_bundle.py from the pinned Cargo.lock
  (nav_graph_core/Cargo.lock) via `cargo metadata --locked
  --filter-platform aarch64-linux-android`; every crate version in that list comes
  straight out of the lockfile.

  The closure is dominated by MIT/Apache-2.0 crates. The one that matters for
  more than attribution is **uniffi** (and its uniffi_* sub-crates), which is
  licensed **MPL-2.0** — a file-level copyleft whose obligations are met by
  shipping the licence text and source availability, not by relicensing the calling
  code. Licence text: licenses/texts/mpl-2.0.txt.

  A few entries (e.g. uniffi_bindgen and the CLI/askama/clap chain) are pulled in
  because nav_graph_core enables uniffi's `cli` feature for its `uniffi-bindgen`
  binary target; they are build-time support rather than code the library calls.
  They are listed anyway — over-attribution is the safe direction here.
